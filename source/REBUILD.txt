Clone the pinned public upstream, then git am Styles_v66.patch.
Alternatively, fetch Styles_v66_from_v65.bundle into the recorded v65 checkout.
Copy rebuild-inputs/single_e/aqua_data.h to local/single_e/aqua_data.h.
Copy rebuild-inputs/single_f/terra_data.h to local/single_f/terra_data.h.
These included headers are exact final build inputs. Never add generated
payloads/private source fixtures to Git.

Install Rust x86_64-pc-windows-gnu plus MinGW GCC/binutils.
cargo build -p kh1-hook --release --target x86_64-pc-windows-gnu
Rename target/x86_64-pc-windows-gnu/release/dinput8.dll to kh1-dual-wield.dll.
Build stamps/PE timestamps can differ. cargo test --workspace runs policy tests.

Optional private fixture regeneration for Single E:
python3 crates/kh1-hook/src/single_e/retime_second.py AQUA_V21_SOURCE TERRA_V4_SOURCE OUTPUT_SOURCE
python3 crates/kh1-hook/src/single_e/generate_data.py OUTPUT_SOURCE local/single_e
The retimer needs Python NumPy and the user's Terra v4 tools/model/MSETs;
it consumes the existing serialized Aqua v21 poses, not a new retarget.

Linux GCC/ctypes offline adapter tests:
Set STYLES_DLL to the absolute final DLL path.
Set AQUA_SOURCE to the retimer's OUTPUT_SOURCE and run single_e/test_runtime.py.
Set TERRA_SOURCE to Terra v4/source, KH1_EXE to the supplied stock Steam Global
executable, STYLES_MENU_ANCHORS to the included styles_menu_anchors.h and
STYLES_SLOT_ANCHORS to the included styles_slots_anchors.h; run single_f/test_runtime.py.
These variables refer to private local files. You can instead run the test files
from their original locations inside the patched repository, where both anchor
paths default to src/single_f automatically.
The real C adapters execute from the final PE. Rust startup/dispatch, most menu drawing
and navigation are mocked; native excerpt execution is in the receipts.
The native AP renderer emits verified draw packets in one test; GPU submission
and native engine cleanup are still substituted, not executed in Windows.
